InventoryBubble Documentation

v1.0.0 · UE 5.6

A translucent sphere that captures a grabbable item, shrinks it, holds exactly one, and hands it back at its original size. Framework-agnostic, Blueprint-first.

    What InventoryBubble is

    A single actor you drop into a level. It floats there as a translucent sphere; push a grabbable item into it and the item shrinks, centres and stays. Pull the item back out and it returns to exactly the size, physics and collision it had before.

    It holds one item. Anything else that overlaps an occupied bubble is left completely alone — it keeps its physics and keeps falling. That constraint is the whole design; it is what makes a bubble readable at a glance in VR.

    It has no hard dependency on any VR framework. It works with the UE5 VR Template, with the VR Expansion Plugin, with a custom grab system, and with no VR at all.

    Drop-in

    Copy into Plugins/, build, enable. No edits to your project's C++ or build files, and no plugin dependencies to enable first.

    Installing and enabling

    1. Copy the InventoryBubble folder into your project's Plugins/ directory. Create Plugins/ if it does not exist.
    2. Close the editor. Right-click your .uproject → Generate Visual Studio project files.
    3. Build the editor target (Development Editor, Win64).
    4. Launch, then Edit → Plugins, search InventoryBubble, tick Enabled, restart.

    The build prints which integration path it took:

    [InventoryBubble] VRExpansionPlugin not found - VRE adapter compiled out.
    Blueprint-only projects

    The plugin has a C++ module, so the project must be able to compile one. Add any C++ class (Tools → New C++ Class → None) to convert the project first.

    60-second quickstart

    1. Drag an Inventory Bubble Actor into the level at chest height (about Z = 120).
    2. Open any physics actor you want storable. In Class Defaults → Actor → Tags, add one entry: Item.
    3. Play. Push the item into the sphere — it shrinks and centres.
    4. Grab it back out — it returns to full size with physics restored.
    The tag goes on the Actor

    Not on the mesh component. It is case-sensitive, and it is the single most common reason a bubble appears to do nothing.

    Anatomy of a bubble

    Four components, and only one of them you normally touch.

    ComponentTypeWhat it does
    Bubble RootSceneRoot. Everything hangs off it
    Bubble MeshStatic MeshThe visible sphere. Never collides, so it cannot block hands or physics items
    Capture VolumeSphereThe overlap trigger. Query-only, overlaps WorldDynamic and PhysicsBody
    Item AnchorSceneWhere a stored item settles, offset by Anchor Offset

    Capture Radius drives both the trigger radius and the mesh scale, so you resize one value and the visible sphere follows. Do not scale the actor itself — that desynchronises the two.

    It works with no content assets

    The plugin ships no .uasset files. The actor loads /Engine/BasicShapes/Sphere and builds its material instance at runtime, so it is functional immediately — just grey rather than translucent blue until you author a material. See Making it look right.

    Events and overrides

    Four events to bind, six functions to override, five to call. That is the whole Blueprint surface.

    EventFires withWhen
    On Item StoredItemThe capture blend finished
    On Item RemovedItemThe item left, however it left
    On Item RejectedItem, ReasonA candidate was refused
    On Bubble State ChangedNew StateAny state transition
    Rejection is deliberately quiet

    On Item Rejected does not fire for a tag mismatch or an invalid actor — the floor, the walls and the player overlap constantly, and firing for those would make the event useless. It fires for Already Occupied, On Cooldown, Held By Player, Interface Refused, Blueprint Refused and Busy.

    Overridable: Can Accept Item, Get Stored Item Transform, On Capture Started, On Capture Finished, On Release Started, On Release Finished. Callable: Try Store Item, Release Item, Force Eject, Clear Cooldowns, Notify Item Grabbed.

    Blueprint recipes

    Only accept keys

    By tag, set Item Tag to Key and move on. By logic, override Can Accept Item:

    Example — filtering by more than a tag 
    Function Can Accept Item (Candidate) -> bool
    ├─▶ Parent: Can Accept Item (Candidate)      ← keep the built-in rules
    └─▶ AND  ( Candidate → Actor Has Tag "Key" )
        ▶ Return

    Always call the parent. Skipping it drops the occupied, cooldown and held-by-player checks, and you will get double captures.

    Auto-eject after a delay

    Example — a bubble that lets go on its own 
    Event On Item Stored (Item)
    └─▶ Set Timer by Event (Time = 5.0, Looping = false) → [Eject]

Custom Event [Eject]
    └─▶ Release Item (Restore Physics = true)

    Clear the timer on On Item Removed, or a player who grabs it early will trip a stale eject.

    Wrist-mounted bubbles

    Add a Child Actor Component to your VR pawn, set its class to your bubble Blueprint, and attach it to the hand mesh.

    Turn off Reject Items Held By Player

    On a wrist bubble the item in the player's other hand is attached to the pawn, so the default held-by-player check refuses it forever. That check exists to stop a bubble snatching from a hand — on a wrist bubble, snatching is the point.

    Per-item rules

    For rules that belong to the item rather than the bubble, add the Inventory Bubble Item interface to the item Blueprint. Implement only what you need — Can Be Stored to veto, Get Stored Scale Multiplier to store at a different size, On Stored In Bubble and On Removed From Bubble to react.

    Making it look right

    The plugin ships no assets, so the intended translucent look is a five-minute material you author once.

    1. In InventoryBubble Content, create a Material named M_InventoryBubble. Enable Show Plugin Content in the Content Browser filter if the folder is hidden.
    2. Set Blend Mode to Translucent and Shading Model to Unlit.
    3. Add a Vector Parameter BaseColor, and Scalar Parameters Opacity (0.35) and EmissiveIntensity (1.0). Wire BaseColor × EmissiveIntensity into Emissive Color, and Opacity into Opacity.
    4. Optionally add a Fresnel driven by FresnelPower and FresnelIntensity for a rim.
    5. Assign it to the bubble's Bubble Material.
    Different parameter names are fine

    The names the bubble writes are themselves properties. Point BaseColorParameterName, OpacityParameterName and EmissiveParameterName at whatever your material uses — no code change.

    Your setupWhat you do

    Three of those five rows say "nothing" because of the layered detection described in the developer guide. The short version: any grab system that re-attaches the item to a hand breaks its attachment to the anchor, and the bubble treats that break as a grab.

    Installing VRE later?

    The probe runs at build time, not at startup. Install VRE, then rebuild.

    The state machine

    Empty→ Capturing→ Occupied→ Releasing→ Empty

    Green states are resting. Amber states are timed blends driven from Tick.

    Two edges skip Releasing and go straight back to Empty:

    • A grab. Blending would fight the hand now holding the item, so release restores instantly whenever the item is held. ForceEject does the same by temporarily zeroing the blend time.
    • The stored item being destroyed. HandleStoredItemDestroyed clears the reference, and Tick re-checks validity every frame as a backstop.

    Ticking

    The actor sets bStartWithTickEnabled = false and RefreshTickEnabled() re-evaluates after every state change. It ticks only while capturing, releasing, occupied with idle motion or grab detection on, flashing a rejection, or drawing debug. An idle empty bubble costs nothing.

    Three-layer grab detection

    Grab systems in Unreal are not standardised. The VR Template's GrabComponent is a Blueprint class with no native type; VRE has IVRGripInterface; most projects roll their own. Rather than pick one, the plugin layers them so the lowest layer always works.

    Layer A

    Core API — the only code that mutates state

    TryStoreItem and ReleaseItem. Everything else in the plugin calls into these. Any grab system can drive the bubble directly, with no dependencies. This is also why the class is testable without a headset.

    Layer B

    Attachment-change detection — zero integration work

    While occupied, CheckForExternalGrab() compares the item's root attach parent against ItemAnchor each tick. Any system that re-attaches the item to a hand breaks that link, and the break is treated as a grab. One pointer comparison per frame.

    Layer C

    Optional adapters — convenience only

    Finds a component whose class name contains GrabComponent and binds its OnGrabbed/OnDropped by reflection. VRE code sits behind #if WITH_VR_EXPANSION_PLUGIN. Never mutates state — it calls NotifyItemGrabbed, which routes into Layer A.

    Layer C binds only to parameterless delegates

    Checked via SignatureFunction->NumParms. Binding a handler with the wrong arity would corrupt the stack when the delegate fires, so a template revision that changes the signature degrades to Layer B rather than crashing. It logs the skip at Verbose.

    The limitation: a grab system that does not re-attach — one driving the item purely by setting its transform each frame — is invisible to Layer B. Those systems must call NotifyItemGrabbed or ReleaseItem.

    The stored-state contract

    The promise is that a released item is indistinguishable from one that was never stored. CaptureItemState snapshots, before changing anything:

    • the actor's world transform and world scale — not relative, so the item is restored to the size it had in the level regardless of what it was attached to in between;
    • the root's previous attach parent and socket;
    • per UPrimitiveComponent: simulate-physics, gravity, collision profile name, collision-enabled, and linear/angular damping.
    Order matters

    Velocities are zeroed before simulation is disabled. Disabling first can leave residual velocity that reapplies the moment physics comes back.

    RestoreItemState replays that snapshot in reverse, scale first. Simulation is re-enabled last and only for components that were simulating originally, so a static mesh that never simulated does not start.

    The UHT interface-default trap

    Worth knowing before you extend the item interface. UnrealHeaderTool generates zero-initialised inline bodies for interface BlueprintNativeEvents:

    virtual bool  CanBeStored_Implementation(const AInventoryBubbleActor* Bubble) const { return false; };
virtual float GetStoredScaleMultiplier_Implementation() const { return 0; };

    Taken as-is, any item implementing the interface without overriding CanBeStored would be silently refused, and a 0 multiplier would scale a stored item to nothing. Both defaults are wrong for this design.

    The fix is two-part: declaring CanBeStored_Implementation in the header suppresses UHT's stub so the real default (true) can be supplied in the .cpp; and the multiplier keeps UHT's 0, which the bubble normalises to 1.0 by treating any value <= 0 as "no override".

    If you add interface members

    The generated default is zero, false or empty. Declare the _Implementation in the header and define it in the .cpp whenever a different default is correct.

    Build-time VRE detection

    InventoryBubble.Build.cs probes for VRExpansionPlugin.uplugin under the host project's Plugins/ and the engine's Plugins/, recursively. On a match it adds the module and defines WITH_VR_EXPANSION_PLUGIN=1; otherwise 0. The macro is always defined, so the #if never becomes an undefined-symbol warning.

    The probe is wrapped in a try/catch: a permissions or reparse-point error while walking the tree must never fail the build, so it is treated as "not installed".

    Build-time, not startup

    Installing VRE after building means a rebuild is required. The build always prints which path it took.

    Adding replication

    Deliberately structured so this stays cheap. No state lives outside StoredItem, BubbleState and StoredState, and the last of those is server-only bookkeeping.

    1. bReplicates = true in the constructor.
    2. Make StoredItem ReplicatedUsing = OnRep_StoredItem, replicate BubbleState, add GetLifetimeReplicatedProps.
    3. Gate TryStoreItem and ReleaseItem on HasAuthority().
    4. In OnRep_StoredItem, run the same blend the server ran — the blend is pure presentation and reads only the two cached transforms.

    No restructuring is required.
